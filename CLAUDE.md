# NPG – Number Portability Gateway UI

Hebrew, RTL admin UI for a national mobile number portability system (Yael Software). It is a pure front-end SPA; the back end is a TIBCO service reached through a `/api` proxy. Originally generated by Lovable, now edited locally.

## Stack
Vite 5 + React 18 + TypeScript, Tailwind + shadcn/ui (Radix) in `src/components/ui/`, MUI 9 (used in some screens), react-router v6, TanStack Query, react-hook-form + zod, xlsx for exports. Package manager: npm.

## Commands
- `npm run dev` – dev server on port **8081**; proxies `/api/*` to `http://localhost:8085` (strips `/api`)
- `npm run lint` / `npm test` (vitest, jsdom) / `npm run build`
- `npm run build:iis` -> `dist-iis/`, `npm run build:apache` -> `dist-apache/` (base `/npg-ui-ai/`)
- `npm run test:e2e` – Playwright tests in `e2e/` (`smoke.spec.ts` + read-only search tests in `search.spec.ts`, shared login in `helpers.ts`). Smoke test: logs in and opens every route, failing on page errors, `/api` 4xx/5xx or error toasts. Runs in installed Edge against the **real TIBCO listener on 8085**, so the listener must be up. Read-only: never add steps that save/delete/add. Test-user credentials (`E2E_USER`, `E2E_PASSWORD`) live in the git-ignored `.env.test`. When adding a route to `App.tsx`, add it to `ROUTES` in the spec.

## Architecture
- `src/App.tsx` – bootstrap: loads LOVs, handles login/session, renders header + routes.
- `src/context/AppContext.tsx` – global state (LOVs, menu, current network, user, token, role). User is persisted in `sessionStorage`.
- `src/services/api.ts` – **all** server calls. `apiRequest(endpoint, payload)` POSTs JSON to `APP_CONFIG.BASE_URL`, sanitises control chars, unwraps `group`/`root`/`getOut`/`LoginResponse` envelopes, toasts errors when code != `1000`, and dispatches `app:config-changed` on code `9999` (app prompts reload). Returns `null` on any failure, so callers must handle `null`.
- `src/components/<Feature>/` – one folder per screen: Process, Calendar, DnRouteNumbers, Event, Messages, NetworksInterfaces, HousekeepingScheduler, NumberingPlan, NumberInquiry, ControlTower, SummaryActivities, CodeTables, Login. Shared widgets in `components/Share/`.
- Menu visibility: `HIDDEN_MENUS` in `components/App/AppConfig.ts` (matched by Hebrew menu names).
- `src/types/` – API response types (`lov.ts`, `menu.ts`, `calendar.ts`).
- Process flow diagrams are static SVG/PNG files in `public/flows/`.

## Runtime configuration
`public/config.js` defines `window.APP_CONFIG` (BASE_URL, LOGIN_REQUIRED, DEFAULT_SELFNETWORKID, ROLE_ID, SESSION_DURATION_MINUTES, LRN_PATTERN, VERSION...). It is loaded by `index.html` **before** the bundle and is edited per deployment without rebuilding, so do not import it; read `(window as any).APP_CONFIG`. Bump `VERSION` when releasing.
`tibco-proxy-ai.conf` is the Apache reverse-proxy snippet for `/api/`.

## Conventions
- UI text, comments and many identifiers are in Hebrew; keep user-facing strings in Hebrew and the layout RTL (`dir="rtl"`).
- Import alias `@` -> `src`.
- Follow the existing component style in the neighbouring files (modals + filters + grid split per screen).
- Prefer the existing `ui/` components over adding new libraries.

## Git workflow
- `main` = released/delivered code. `develop` = integration branch. Never commit directly to either.
- For every change: branch from `develop` (`feature/<short-name>` or `fix/<short-name>`), commit there, run `npm run lint`, `npm test`, `npm run test:e2e`, then **stop and let the user test it locally** (dev server on 8081 against the TIBCO test environment).
- Merge to `develop` only after the user approves; merge `develop` to `main` only when the user asks for a release. Never push or merge without being asked.
- "develop" is a git branch, not a deployed environment.

## Things to be careful about
- `dist-iis/` and `dist-apache/` are the deliverables handed to the customer and are intentionally tracked in git (`dist/` is ignored). Never hand-edit them; regenerate with the matching npm script, only when asked to prepare a release, and bump `VERSION` in `public/config.js` first.
- `.env` is git-ignored (untracked). Do not put secrets in it.
- `.env` contains a malformed line (`VITE_LOGIN_REQUIRED:"Y",`) and appears unused; the real config lives in `public/config.js`.
- `package.json` name is still the Lovable default; README is the Lovable template and is out of date.
- Unit coverage is thin: `src/test/api.test.ts` covers `apiRequest` and `formatForTibco` only. Verify UI changes with `npm run lint`, `npm run build`, and `npm run test:e2e`.
